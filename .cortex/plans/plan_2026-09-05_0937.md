## Context

**Source tables:** 4 Bronze AP invoice tables in `COCO_WORKSHOP.SOURCE_DATA` (SAP: 15 rows, Oracle: 15 rows, Baan: 10 rows, Workday: 10 rows). All share the same conceptual structure but use source-specific column names, code formats, and status vocabularies.

**Target schema:** `COCO_WORKSHOP.PIPELINE_LAB` — currently empty.

**Key findings from data inspection:**
- **Payment terms** have 4 formats: `NET30`, `N30`, `Net 30`, `NET60`/`N60`/`Net 60`
- **Status values** have 6 distinct strings across sources: `APPROVED`, `PENDING`, `VALIDATED` (Oracle), `POSTED` (Baan), `Approved`/`In Review` (Workday — mixed case)
- **GL accounts** use incompatible coding schemes (`5100-10` vs `A5100-40` vs `GL-510` vs `LA-6200`)
- **Cost center / dept** use incompatible granularity (`CC-ENG-01` vs `D-ENG` vs `BC-MFG` vs `WCC-TECH`)
- Source-specific columns: `SAP_COMPANY_CODE`, `SAP_DOCUMENT_TYPE`, `ORACLE_ORG_ID`, `ORACLE_SOURCE`, `BAN_COMPANY`, `WD_TENANT_ID`

## Implementation steps

### Step 1 — Create `SILVER_AP_INVOICES` as a Dynamic Table in `PIPELINE_LAB`

A single Dynamic Table that unions all 4 Bronze sources with a canonical column schema:

| Silver column | Type | Mapping logic |
|---|---|---|
| `INVOICE_SK` | TEXT | Pass-through source key (`SAP-001`, `ORA-001`, etc.) — already globally unique |
| `SOURCE_SYSTEM` | TEXT | Literal: `'SAP'`, `'ORACLE'`, `'BAAN'`, `'WORKDAY'` |
| `INVOICE_NUMBER` | TEXT | Direct map from each source's invoice-number column |
| `VENDOR_ID` | TEXT | Source vendor/supplier ID as-is (no cross-system matching) |
| `VENDOR_NAME` | TEXT | Direct map |
| `INVOICE_DATE` | DATE | Direct map |
| `DUE_DATE` | DATE | Direct map |
| `INVOICE_AMOUNT` | NUMBER(38,2) | Direct map |
| `CURRENCY_CODE` | TEXT | Direct map (already ISO codes in all sources) |
| `PAYMENT_TERMS` | TEXT | **Normalize** to `NET30` / `NET60` via `UPPER(REPLACE(..., ' ', ''))` then prefix `NET` if missing |
| `PO_NUMBER` | TEXT | Direct map (preserve source prefixes) |
| `LINE_DESCRIPTION` | TEXT | Direct map |
| `GL_ACCOUNT_RAW` | TEXT | Source GL code **as-is** — no stripping/normalization (per open question #3) |
| `COST_CENTER_RAW` | TEXT | Source cost center / dept code **as-is** (per open question #1) |
| `INVOICE_STATUS` | TEXT | **Normalize** to uppercase: `UPPER(...)`. This produces `APPROVED`, `PENDING`, `VALIDATED`, `POSTED`, `IN REVIEW` — all preserved as distinct values, no collapsing (per open question #2) |
| `CREATED_AT` | TIMESTAMP_NTZ | Direct map |
| `SOURCE_ENTITY_CODE` | TEXT | Collapse source-specific org identifiers: `SAP_COMPANY_CODE`, `ORACLE_ORG_ID`, `BAN_COMPANY`, `WD_TENANT_ID` |
| `SOURCE_DOCUMENT_TYPE` | TEXT | `SAP_DOCUMENT_TYPE` for SAP, `ORACLE_SOURCE` for Oracle, `NULL` for Baan/Workday |

**Design decisions baked in:**
- Payment terms: safe normalization (only format, not semantics)
- Status: case-normalize only, keep all 5 distinct values visible — no silent equivalence mapping
- GL + cost center: carry raw values; a future conformance layer can map them
- Vendor IDs: no cross-system dedup at this layer

### Step 2 — Write and execute the DDL

Create the Dynamic Table with `TARGET_LAG = '1 hour'` against the 4 Bronze tables using `UNION ALL` with per-source `SELECT` blocks.

### Step 3 — Validate

- Row count check: Silver should have exactly 50 rows (15 + 15 + 10 + 10)
- Spot-check: verify a sample row from each source maps correctly
- Confirm no NULLs in non-nullable columns (`INVOICE_SK`, `SOURCE_SYSTEM`, `INVOICE_DATE`, `INVOICE_AMOUNT`)
- Confirm payment-terms normalization produced only `NET30` and `NET60`
- Confirm status values are the expected 5 distinct uppercase values
